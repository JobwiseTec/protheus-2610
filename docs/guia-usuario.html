Protheus 12.1.2610 em Docker com DeskFlow Control

Guia do usuário: download, primeira subida, acesso ao Protheus e operação pelo DeskFlow · imagens emebatista/*-2610 no Docker Hub · repositório github.com/emebatista/docker-protheus-2610

O que você vai ter ao final: um Protheus 12.1.2610 completo (AppServer 26.3, DBAccess 26.1, License Server 3.7.2, Postgres 15 com base de demonstração, SmartView 3.11) rodando em containers na sua máquina, com o DeskFlow Control como painel de operação em http://localhost:8073. Nada é instalado fora do Docker; para remover, basta apagar os containers e volumes.

2. Download

Baixe o repositório inteiro — ele traz o docker-compose.yml, o conf.inf e a pasta deskflow/ (configuração do DeskFlow). Duas formas:

git clone https://github.com/emebatista/docker-protheus-2610.git
cd docker-protheus-2610

ou, no GitHub, botão Code → Download ZIP, descompacte e entre na pasta. A estrutura deve ficar assim:

docker-protheus-2610/
├── docker-compose.yml      ← todos os serviços, incluindo o DeskFlow
├── conf.inf                ← credenciais do Postgres usadas pelo DBAccess
├── deskflow/
│   ├── config.json         ← topologia "Protheus 2610 (Docker)" já configurada
│   ├── deskflow.ini        ← parâmetros do DeskFlow (licença entra aqui)
│   └── nginx/deskflow.conf ← proxy da interface web
└── README.md

Não renomeie nem mova os arquivos: o DeskFlow lê o docker-compose.yml e o conf.inf dessa pasta para controlar os containers.

3. Primeira subida

  1. Abra um terminal dentro da pasta do projeto.
  2. Entre no Docker Hub (digite usuário e senha quando pedido): 
    docker login
  3. Suba tudo: 
    docker compose up -d
    O Docker baixa as sete imagens (~10 GB) e cria o grupo protheus2610 com os containers postgresql-2610, license-server-2610, dbaccess-2610, protheus-2610, smartview-2610, deskflow-2610 e deskflow-web-2610. O container protheus-2610-exclusivo fica cadastrado, mas só sobe quando o DeskFlow ativa o modo exclusivo.
  4. Aguarde o banco. Na primeira subida o Postgres cria a base protheus e restaura o seed 12.1.2610 (203 MB comprimidos → ~2 GB). Leva de 2 a 10 minutos conforme a máquina. Acompanhe no Docker Desktop (container postgresql-2610 → Logs) ou com: 
    docker compose logs -f db
    Está pronto quando aparecer Restore Finished. Base Protheus 12.1.2610 pronta. seguido de PostgreSQL init process complete; ready for start up.

Enquanto o banco restaura, o AppServer reinicia sozinho algumas vezes (não encontra o DBAccess/banco). É normal; ele estabiliza assim que o Postgres responde.

Volumes criados automaticamente: protheus12 (binários, RPO, dicionários e logs do AppServer), protheus12-exclusivo, protheus12-license, dbaccess-multi e a pasta de dados do Postgres. Eles são preenchidos a partir das imagens e preservam alterações (INIs editados, patches aplicados, dados) entre reinícios e recriações dos containers.

4. DeskFlow Control: primeiro acesso

  1. Abra http://localhost:8073.
  2. Usuário admin, senha msadm.
  3. Troque a senha: Configuração → Usuários → admin.

No menu lateral, Topologias lista "Protheus 2610 (Docker)" (AppServer, exclusivo e SmartView), "DbAccess" (DBAccess e Postgres) e "License Server". Clique na primeira: a aba Serviços mostra cada container como um serviço, com status, portas em uso e botões iniciar / parar / reiniciar.

Use esta tela para confirmar que a subida terminou: protheus-2610.sh e smartview-2610.sh em Running; na topologia DbAccess, postgres-2610.sh e dbaccess-2610.sh em Running; o exclusivo fica Stopped por padrão.

6. Configurações iniciais no Configurador

  1. Tipo de ambiente: SIGACFG → Ambiente → Cadastros → Configuração do Tipo de Ambiente → "Desenvolvimento" (já vem assim na base de demonstração; confirme).
  2. Conferir a release: dentro do Configurador pressione Shift+F6 (Central de Diagnóstico). Deve mostrar Release do RPO e do dicionário 12.1.2610, AppServer 26.3.0.0, DBAccess 26.1.0.0, License Server 3.7.2, WebApp 26.0.0.
  3. SmartView: veja a seção 7.

7. SmartView

O SmartView (relatórios e análises) já sobe no container smartview-2610:

  • Aplicação: http://localhost:7017 — login com o usuário do Protheus (admin e a senha acima).
  • Agente/diagnóstico: http://localhost:7019/diagnostic (status do serviço, versões instaladas); http://localhost:7019/startup para reconfigurar.

Para o Protheus abrir os relatórios no formato SmartView, cadastre a URL no Configurador: SIGACFG → Ambiente → Cadastros → Configuração Smart View → autenticação Token Protheus → Avançar → URL base http://<IP da sua máquina>:7017 → Testar conexão → Confirmar.

Use o IP real da máquina (ex.: http://192.168.0.10:7017), nunca localhost ou 127.0.0.1: quem chama essa URL é o AppServer de dentro do container. Descubra o IP com ipconfig (Windows) ou ipconfig getifaddr en0 (macOS). Se o IP mudar (outra rede), refaça o cadastro. Dentro do SmartView, nos conectores, informe o mesmo IP.

8. Operação do dia a dia pelo DeskFlow

Depois da primeira subida, você não precisa mais do docker compose: tudo passa pelo DeskFlow.

TarefaOnde
Parar / iniciar / reiniciar um serviço ou todosTopologia → Serviços → botões por linha ou Iniciar/Parar/Reiniciar no topo.
Modo exclusivo (manutenção na base)Serviços → Ativar Exclusivo: para o AppServer normal e sobe o protheus-2610-exclusivo (SmartClient porta 1235 / WebApp 4322, sem REST). Desativar Exclusivo devolve tudo ao normal.
Ver o log do AppServer em tempo realServiços → ícone do olho na linha do serviço: console.log ao vivo com filtro por palavra-chave e download.
Editar appserver.ini / dbaccess.iniServiços → ícone do lápis (edição com validação e backup automático) ou menu Arq. Ini → comparar seções.
Ambientes e RPOAba Ambientes: promover RPO entre ambientes, comparar, rollback, aplicar pacotes (PTM/PAK/UPD), atualizar dicionário.
Auditoria da topologiaAba Auditoria: checagens de INIs, ambiente principal, sourcepaths, binários e compilador, com semáforo.
Saúde geralVisão Executiva: topologias saudáveis, serviços operacionais, riscos e atividade do período.
RastreabilidadeLog de Ações: quem fez o quê, quando, com resultado.
AgendamentosAba Scheduler: restart programado, promoções, patches por cron ou intervalo.
AtalhosAba Atalhos: WebApp, WebMonitor, SmartView, License Server já cadastrados.

O item "Compilador configurado" da auditoria aparece em amarelo até você gerar o compilador da topologia (Configuração → Topologias → Gerar Compilador). Não impede nada do que está neste guia.

10. Atualizar, recriar e remover

  • Parar tudo (preservando dados): docker compose stop. Subir de novo: docker compose start (ou pelo Docker Desktop).
  • Baixar imagem nova de um serviço e recriá-lo: 
    docker compose up -d --no-deps --force-recreate --pull always protheus
    (idem license, db, dbaccess, smartview, deskflow). Os volumes nomeados preservam INIs, RPO e dados.
  • Voltar um volume ao conteúdo original da imagem (ex.: desfazer alterações no AppServer): 
    docker compose stop protheus
docker volume rm protheus2610_protheus12
docker compose up -d protheus
  • Recomeçar o banco do zero: parar tudo, apagar a pasta volume/data/psql (ou o volume do banco) e subir; o seed é restaurado de novo.
  • Remover tudo: docker compose down -v (apaga containers e volumes) e, se quiser liberar disco, docker image rm das imagens emebatista/*-2610.
  • DeskFlow: a configuração, os dados e a licença ficam na pasta deskflow/ do projeto; recriar o container não os perde. Atualizações do DeskFlow vêm pela imagem (--pull always deskflow).

11. Problemas comuns

SintomaCausa provável / solução
Container não sobe no Mac Apple SiliconRosetta ligada no Docker Desktop. Desligue (Settings → General) e reinicie o Docker.
port is already allocatedOutra versão (2410/2510) ou outro programa usando a porta. Pare os containers antigos ou mude a porta publicada no compose.
Protheus não abre logo após o upBanco ainda restaurando. Espere o Restore Finished no log do Postgres; o AppServer reinicia sozinho.
WebApp fica em brancoSessões abandonadas (abas fechadas sem Log Off). No DeskFlow, reinicie o protheus-2610.sh. No macOS confirme que o WebAgent está aberto.
"Falha ao conectar com o WebAgent" (macOS)Instale/abra o WebAgent da TOTVS (porta 21021) e recarregue o WebApp.
SmartView: "Teste da conexão" falha no ConfiguradorURL com localhost. Use o IP real da máquina; confira http://localhost:7019/diagnostic (servidor deve estar ativo na versão 3.11.x).
REST (8181) não responde após parada bruscaReinicie o protheus-2610.sh pelo DeskFlow; o REST volta em ~1 minuto.
DeskFlow mostra serviço Stopped que está rodandoO DeskFlow lê o status pelo Docker; aguarde o ciclo de 30 s ou clique em atualizar. Se persistir, verifique se o grupo do compose se chama protheus2610 (nome fixo no arquivo).
DeskFlow "Licença expirada"Veja a seção 12.
Pouca memória / lentidãoAumente os recursos do Docker Desktop (8 GB+). Pare o SmartView se não for usá-lo (pelo DeskFlow).

12. Licença do DeskFlow

Este pacote demonstra o produto completo; para usar no seu ambiente (VM ou servidor físico, Linux ou Windows, com seus AppServers reais), solicite uma licença de avaliação ou comercial em https://deskflow.com.br (Contato) ou pelo e-mail emebatista@hotmail.com, informando empresa e quantidade de servidores. Você receberá tenant_code, tenant_name e tenant_authorization; grave-os no deskflow/deskflow.ini (seção [setup]), reinicie o container deskflow-2610 e confira o selo Licenciado no topo da tela. A renovação é automática (job diário) enquanto o servidor de licenças estiver acessível.
